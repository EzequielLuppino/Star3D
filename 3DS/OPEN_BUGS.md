## Render capture (bugs 7, 8)

Each mark (L+R+SELECT, Settings > "Log snapshot (mark)", remote `mark`) writes `sdmc:/3ds/star3d/captures/YYYYMMDD_HHMMSS_f<frame>/` over 5 frames. `info.txt` explains each file:
- color/alpha/depth.bmp, plus depth.bin (raw u32), for the marked frame.
- copyN.ppm: EFB copies.
- id.bmp + states.txt: state index per pixel, plus the TEV/texture/light dump of each state. Decode a pixel as R/17 + 16*G/17 + 256*B/85, then look for `state #N` in states.txt. The colour holds only 10 bits: with more than 1024 states the index wraps (N, N + 1024 look the same). Krazoa in the rain has ~1475 states, and its last full-screen filter (#1355 -> colour 331) covers the whole ID image (bug 33).
- tint.bmp: TEV fallbacks.
- light.bmp: vertex color only. Black means the channel is off: Fox and most models are lit by ramp textures generated from their normals (texgen src 1).
- normals.bmp: view-space normals.

Images are 400x240 landscape. Verified on Azahar (island, 2026-10-10).

User-assisted capture (since 2026-10-10): the user drives Azahar to the bug and takes the mark. The session names the scene, angle and env.txt switches, then reads the newest capture folder. Scripted navigation is unreliable:
- the title attract demo cycles scenes, so the frame numbers of old captures don't repeat;
- blind stick input walked Fox into a save point.

## Soak diagnostics (bug 6)

- Every 600 frames a `diag` block in Star3D.log: dlcache fill/tombstones/full/rehash, texcache fill/tombstones/trimmed, free linear/VRAM/heap, offscreen targets ok/failed bitmasks, shadows on
- `once` lines: LOG_ONCE sites that start firing (counted, with hit totals)
- `badvtx` lines: NaN or huge positions (> 1e6) / matrices (> 1e7), with caller address (look up in out/star3d.elf)
- Mark snapshot (`--- mark N ---`): L+R+SELECT, Settings > "Log snapshot (mark)", or the remote `mark` command. Adds player position, the last 8 bad values and every LOG_ONCE count. Remote `stats` logs the block on demand
- `dl` line also has `evict` (LRU evictions for a slot), `cold` (entries unused for 1800 frames) and the frame of the last pool reset. The `tex` line has `vram ... (min N)`, the VRAM free low-water mark
- `draw` line: dropped draws (count, vertices, frames, last frame), per-frame peaks of the frame vertex/index/dyn buffers against their sizes, dyn buffer fails, GXCopyTex copies done/skipped, offscreen target misses, `posmtx culls` (position matrices with a translation over 1e6, replaced with zero)
- Every mark also logs a one-frame render `census` on the next frame: states/draws/tris by vertex path, z test/func/write counts, blend/alpha test/cull/projection, vertex shader and combiner/unit counts, 2-pass/water/fog, each distinct depth mapping (viewport near/far, projection z terms, the C3D_DepthMap it gets, states and tris), and the first 48 states one per line
- Log rotates at 4 MB to sdmc:/3ds/star3d/Star3D.1.log, so a long session needs both files
